## Descripción

Añadir la capa de persistencia EF Core sobre SQLite al proyecto `Infrastructure`. Configurar `TradingDbContext`, mappings explícitos por `IEntityTypeConfiguration<T>`, registrar el contexto en DI desde `Web/Program.cs`, ejecutar migración inicial y aplicarla al arrancar la app. SQLite local en `App_Data/trading.db`.

## Objetivo

A partir de HV-003 cualquier servicio Application/Infrastructure puede hidratar `Trade`/`MarketTick`/`PortfolioSnapshot` desde BD. Migration inicial commiteable y reproducible. La app arranca, crea/actualiza la BD automáticamente, y queda lista para HV-004 (BackgroundService de ticks).

### 2. Interfaz `ITradingDbContext` (Application)

`Application/Common/Interfaces/ITradingDbContext.cs`

```csharp
using EnsenameLaPasta.Domain.Entities;
using Microsoft.EntityFrameworkCore;

namespace EnsenameLaPasta.Application.Common.Interfaces;

public interface ITradingDbContext
{
    DbSet<Trade> Trades { get; }
    DbSet<MarketTick> MarketTicks { get; }
    DbSet<PortfolioSnapshot> PortfolioSnapshots { get; }

    Task<int> SaveChangesAsync(CancellationToken cancellationToken = default);
}
```

> Application **referencia** EF Core (`Microsoft.EntityFrameworkCore`) solo para los tipos `DbSet<T>` y la firma `SaveChangesAsync`. Es un compromiso pragmático aceptado en muchos repos Clean: alternativa más pura sería definir `IQueryable<T>` y un patrón Repository, pero añade complejidad innecesaria al MVP.

Esto requiere añadir paquete:

### 3. `TradingDbContext` (Infrastructure)

`Infrastructure/Persistence/TradingDbContext.cs`

```csharp
using EnsenameLaPasta.Application.Common.Interfaces;
using EnsenameLaPasta.Domain.Entities;
using Microsoft.EntityFrameworkCore;

namespace EnsenameLaPasta.Infrastructure.Persistence;

public sealed class TradingDbContext : DbContext, ITradingDbContext
{
    public TradingDbContext(DbContextOptions<TradingDbContext> options) : base(options) { }

    public DbSet<Trade> Trades => Set<Trade>();
    public DbSet<MarketTick> MarketTicks => Set<MarketTick>();
    public DbSet<PortfolioSnapshot> PortfolioSnapshots => Set<PortfolioSnapshot>();

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.ApplyConfigurationsFromAssembly(typeof(TradingDbContext).Assembly);
    }
}
```

### 4. Configuraciones EF Core

`Infrastructure/Persistence/Configurations/TradeConfiguration.cs`

```csharp
using EnsenameLaPasta.Domain.Entities;
using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Metadata.Builders;

namespace EnsenameLaPasta.Infrastructure.Persistence.Configurations;

internal sealed class TradeConfiguration : IEntityTypeConfiguration<Trade>
{
    public void Configure(EntityTypeBuilder<Trade> builder)
    {
        builder.ToTable("Trade");
        builder.HasKey(t => t.Id);

        builder.Property(t => t.Symbol).IsRequired().HasMaxLength(20);
        builder.Property(t => t.EntryPrice).HasColumnType("TEXT").HasConversion<string>();
        builder.Property(t => t.ExitPrice).HasColumnType("TEXT").HasConversion<string?>();
        builder.Property(t => t.Quantity).HasColumnType("TEXT").HasConversion<string>();
        builder.Property(t => t.Status).HasConversion<int>();

        builder.HasIndex(t => new { t.Symbol, t.CreatedAt });
        builder.HasIndex(t => t.Status);
    }
}
```

> **Nota SQLite**: SQLite no tiene tipo `decimal` nativo. Hay dos enfoques:
> 1. Almacenar como `TEXT` (string) con `HasConversion<string>()`: precisión total preservada.
> 2. Almacenar como `REAL` (double): pierde precisión en valores grandes.
>
> **Elegimos opción 1 (TEXT)**. Es la práctica recomendada para datos financieros en SQLite. El cast es manejado por EF Core con `HasConversion<string>()`.

### 5. `DependencyInjection` extension de Infrastructure

`Infrastructure/DependencyInjection.cs`

```csharp
using EnsenameLaPasta.Application.Common.Interfaces;
using EnsenameLaPasta.Infrastructure.Persistence;
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.Configuration;
using Microsoft.Extensions.DependencyInjection;

namespace EnsenameLaPasta.Infrastructure;

public static class DependencyInjection
{
    public static IServiceCollection AddInfrastructure(this IServiceCollection services, IConfiguration configuration)
    {
        var connectionString = configuration.GetConnectionString("Default")
            ?? throw new InvalidOperationException("ConnectionString 'Default' no configurada.");

        services.AddDbContext<TradingDbContext>(options =>
            options.UseSqlite(connectionString));

        services.AddScoped<ITradingDbContext>(sp => sp.GetRequiredService<TradingDbContext>());

        return services;
    }
}
```

### 6. `Web/Program.cs` actualizado

Cambiar el template MVC default por:

```csharp
using EnsenameLaPasta.Infrastructure;
using EnsenameLaPasta.Infrastructure.Persistence;
using Microsoft.EntityFrameworkCore;

var builder = WebApplication.CreateBuilder(args);

// Asegurar carpeta App_Data
var appDataPath = Path.Combine(builder.Environment.ContentRootPath, "App_Data");
Directory.CreateDirectory(appDataPath);

builder.Services.AddControllersWithViews();
builder.Services.AddInfrastructure(builder.Configuration);

var app = builder.Build();

// Aplicar migraciones automáticamente al arrancar
using (var scope = app.Services.CreateScope())
{
    var db = scope.ServiceProvider.GetRequiredService<TradingDbContext>();
    await db.Database.MigrateAsync();
}

if (!app.Environment.IsDevelopment())
{
    app.UseExceptionHandler("/Home/Error");
    app.UseHsts();
}

app.UseHttpsRedirection();
app.UseRouting();
app.UseAuthorization();
app.MapStaticAssets();
app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}")
    .WithStaticAssets();

app.Run();
```

> **Auto-migration al arrancar** es aceptable para una app personal SQLite. En entornos multi-instancia se haría con un script separado.

## Notas de implementación

- **Precisión decimal con SQLite**: forzamos `HasConversion<string>()` en todos los `decimal`. Es el patrón recomendado para datos financieros. Performance no es crítico (es un simulador local).
- **Auto-migrate al arrancar**: cómodo y aceptable para app personal local. En producción multi-instancia se evita (usaría `dotnet ef database update` como deploy step).
- **`AllowedHosts: "*"`**: violaría la regla global `allowedhosts-hardening.md` en producción Comillas, pero esto NO es producción Comillas. Documentado en spec para evitar futuras revisiones por hook.
- **Sin `_atlas/` para esto**: no aplica ninguna rule específica de SQL Server (regla `database.md` apunta a SQL Server 2017+ Comillas). SQLite es excepción documentada del MVP.
- **Tests con `:memory:`**: cada test crea una BD nueva (constructor) y la destruye (Dispose), evitando dependencias entre tests.

### Lecciones Aprendidas

1. **`dotnet-ef` es global tool, no NuGet de proyecto**: hay que instalarla con `dotnet tool install --global dotnet-ef --version 10.0.*`. Si se cambia de máquina, hay que reinstalar. Considerar añadirla como tool local (`.config/dotnet-tools.json`) en el futuro para que sea reproducible en CI.
2. **SQLite + `decimal` requiere `HasConversion<string>()`**: el approach de TEXT vs REAL es decisión de proyecto. TEXT preserva precisión, REAL es más rápido. Para datos financieros, siempre TEXT. La migration generada confirma: todas las columnas decimal son `TEXT`, no `REAL`.
3. **Modo WAL activado por defecto en EF Core 10 / SQLite**: aparecen archivos `*.db-shm` y `*.db-wal`. Es correcto y beneficia concurrencia. Ya están en `.gitignore` por el patrón `App_Data/*.db*`.
4. **`MigrateAsync()` al arrancar es seguro con `__EFMigrationsLock`**: EF Core 10 introdujo este lock automático para evitar problemas de race en arranques concurrentes. No es algo que se vea con SQLite local pero está bien que esté ahí.
5. **Tests con `:memory:` requieren mantener la conexión abierta**: cerrar la `SqliteConnection` destruye la BD. Por eso `_connection.Open()` en el constructor y `_connection.Dispose()` en `Dispose()`. Cada test crea un `DbContext` nuevo pero comparte la misma conexión `:memory:`.
6. **Las firmas `HasConversion<string?>()`** funcionan para `decimal?` en .NET 10 (Nullable Reference Types friendly).
