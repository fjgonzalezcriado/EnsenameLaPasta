# HV-058: Fix variación acumulada del rango 1D (cierre anterior, no apertura de hoy)

## Información General
- **Código**: HV-058
- **Fecha inicio**: 2026-11-02
- **Estado**: ✅ Completado
- **Prioridad**: 🟠 Media (dato incorrecto visible en cabecera)
- **Tipo**: Bugfix
- **Depende de**: HV-037 (variación acumulada del rango)

## Contexto
El usuario reportó que la variación acumulada mostrada en el rango **1D** no coincidía con la de onvista.de: para HY9H.F, onvista mostraba `978,00€ - +6,07% - +56,00€`, mientras la app mostraba un valor distinto. Diagnóstico: `updateChartDelta` (HV-037, `dashboard.js`) usa siempre `pts[0]` (primer punto de la serie devuelta) como base del cálculo. Para rangos como 1M/5D eso es correcto (rentabilidad del periodo = primer punto de la ventana vs último). Pero para **1D**, `pts[0]` es el primer tick intradía de **hoy** (la apertura de la sesión), no el **cierre de ayer** — que es la convención financiera real para "variación diaria" (la que usa onvista, Yahoo Finance, Google Finance, cualquier bolsa).

Verificado contra la API real de Yahoo (`/v8/finance/chart`, `meta.previousClose`): para HY9H.F, `previousClose=924`, precio actual `976` → delta correcto `+52,00€ (+5,63%)`. Con el cálculo antiguo (`pts[0]=978` como base) el resultado era `-2,00€ (-0,20%)` — signo y magnitud erróneos.

## Causa raíz
`YahooHistoryProvider`/`IMarketHistoryProvider` nunca exponían `meta.previousClose` (solo parseaban los arrays `timestamp`/`close`/`volume`/OHLC). El frontend no tenía ese dato disponible, así que usaba el único punto de referencia que sí tenía: el primero de la serie.

## Solución
- Nueva capacidad `IPreviousCloseProvider` (Application), separada de `IMarketHistoryProvider` porque no todos los proveedores la soportan (Twelve Data / Alpha Vantage no la implementan).
- `YahooHistoryProvider` la implementa: pide `/v8/finance/chart/{symbol}?range=1d&interval=5m` (mismo range/interval que ya usa `GetHistoryAsync` para "1D") y lee `meta.previousClose`, con fallback a `meta.chartPreviousClose` (Yahoo renombra el campo según el `interval` usado — descubierto durante la implementación, ver Notas). Degrada a `null` sin lanzar.
- `SelectableMarketHistoryProvider` delega la nueva capacidad solo cuando Yahoo es el proveedor activo (mismo criterio de fallback que ya usa para el histórico); con Twelve Data/Alpha Vantage activos devuelve `null` sin tocar la red.
- `DashboardController.History` solo pide el cierre anterior cuando `range == "1D"` (en el resto de rangos no aplica y sería una llamada HTTP desperdiciada); lo añade al nuevo campo `PriceSeriesDto.PreviousClose` (nullable, default `null` — no rompe los otros 2 call sites existentes).
- `dashboard.js` → `updateChartDelta`: si `win.range === '1D'` y `s.previousClose > 0`, usa ese valor como base del delta; en cualquier otro caso (otros rangos, o 1D sin dato disponible) mantiene el comportamiento anterior (`pts[0]`) — sin regresión para 5D/1M/etc. ni si Yahoo no está activo.

## Notas de Implementación
- **Hallazgo durante la implementación**: Yahoo nombra el campo del cierre anterior de forma distinta según el `interval` de la petición — con `interval=5m` es `meta.previousClose`; con `interval=1d` es `meta.chartPreviousClose` (confirmado contra el endpoint real). El primer intento usaba `interval=1d` y devolvía siempre `null` en el smoke test; corregido a `interval=5m` (coherente con lo que ya usa `GetHistoryAsync` para "1D") + fallback a ambos nombres por robustez ante símbolos que puedan comportarse distinto.
- Se evitó ampliar `IMarketHistoryProvider` (usado por 18 archivos, incluyendo `SsaPriceForecaster`/`MlDirectionClassifier` que no necesitan este dato): la nueva capacidad vive en una interfaz separada y opcional, para no arrastrar cambios a consumidores no relacionados.
- Dos falsos positivos de SonarAnalyzer (regla S125, comentarios de prosa con `;` — ya documentado en `dotnet-code-style.md`) corregidos reescribiendo el comentario sin punto y coma.
