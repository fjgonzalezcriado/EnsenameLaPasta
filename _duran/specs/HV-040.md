## Contexto
HV-039 fijó el margen del eje Y en ±20 unidades (absoluto), que se ajusta bien a HY9H.F (~1400) pero es desproporcionado para instrumentos de precio muy bajo. En vez de un margen relativo fijo, el usuario pidió un **selector** para controlar el margen (compresión ↔ extensión del eje Y).

## Solución (solo frontend, sin migración)
- Nuevo selector `#yMarginSelect` en la barra de controles del gráfico: **Ajustado** (0 %, máxima extensión) · **±1 %** · **±2 %** · **±5 %** · **±10 %** · **±20 %** (más compresión).
- El margen es **relativo al precio medio** del rango: `margin = ((techo + suelo) / 2) × yMarginPct`; `yMin = suelo − margin`, `yMax = techo + margin`. Funciona igual en cualquier instrumento (1400 o 3).
- `Ajustado` (0 %) deja la línea pegada a los bordes (máxima extensión); con datos planos + 0 % se aplica un epsilon mínimo para no tener un eje de rango nulo.
- Estado `yMarginPct` (default 0.02) persistido en `localStorage` (`chartYMargin`). El cambio recalcula el eje **sin refetch** (re-render con `lastRenderedSeries`).
- Las líneas discontinuas de techo/suelo (HV-039) se mantienen.

## Criterios de aceptación
- [x] Selector con opciones Ajustado/±1/±2/±5/±10/±20 %
- [x] El margen es relativo al precio (no absoluto) → válido para cualquier instrumento
- [x] Cambiar el selector recalcula el eje al instante sin recargar el histórico
- [x] La preferencia se conserva entre sesiones (localStorage)
