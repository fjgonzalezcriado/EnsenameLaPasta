# HV-035: Fix — el histórico no debe romper con símbolos no válidos (404)

## Síntoma
Al cambiar el proveedor a **Twelve Data**, el programa paraba con `HttpRequestException 404` en `TwelveDataHistoryProvider.GetHistoryAsync` (`EnsureSuccessStatusCode`). Causa: tras el cambio, el frontend recarga el histórico del símbolo seleccionado, que era estilo Yahoo (`^GSPC`, `HY9H.F`) y **no existe en Twelve Data** → HTTP 404 → excepción; el `DashboardController.History` solo capturaba `ArgumentException`, así que la excepción quedaba sin controlar (500 / el depurador para).

## Solución
- `TwelveDataHistoryProvider` y `YahooHistoryProvider`: ante respuesta no exitosa (404, etc.) o `status:"error"` → **log + devolver serie vacía** (no lanzar). Un símbolo no válido para el proveedor no es un fallo del programa.
- `DashboardController.History`: `catch` amplio (salvo cancelación) → devuelve `PriceSeriesDto` vacío y loguea, para que ningún fallo del proveedor produzca un 500.
