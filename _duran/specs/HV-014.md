## Objetivo
Introducir el concepto de **caja/efectivo** para una visión de **cuenta completa**: efectivo aportado (ingresos/retiradas), efectivo disponible y valor de cuenta (efectivo + cartera).

## Modelo
- `cash (disponible) = aportado_neto − invertido(abiertas) + realizado(cerradas)`
- `valor_de_cuenta = cash + valor_de_mercado(abiertas)`
- Invariante: `valor_de_cuenta = aportado_neto + PnL_total`.

Las compras restan efectivo y las ventas lo suman; eso ya está implícito porque el efectivo se **deriva** de las posiciones + movimientos (no se almacena un saldo).

## Especificaciones
### Backend
- Entidad `CashMovement(Id, Amount, Note, CreatedAt)` (Amount &gt; 0 ingreso, &lt; 0 retirada) + `CashMovementConfiguration` (Amount→TEXT) + `DbSet` + migración `AddCashMovement`.
- `ICashService`/`CashService`: `GetMovementsAsync`, `GetNetDepositsAsync`, `AddAsync(amount, note, at?)`, `DeleteAsync(id)`. DI scoped.
- `DashboardDto`: + `NetDeposits`, `Cash`, `AccountValue`. `DashboardService` los calcula (lee `CashMovements` y reutiliza invested/realizedPnL/marketValue).
- `CashController`: `GET /api/cash/movements`, `POST /api/cash` `{amount,note}`, `DELETE /api/cash/{id}`.

### Frontend
- Métricas reorganizadas a **6 tarjetas**: Valor de cuenta · Efectivo (aportado) · Valor de cartera (invertido) · PnL total · Posiciones · Winrate.
- Botón "💰 Caja" → **modal** con alta de Ingreso/Retirada (importe + nota) y lista de movimientos con borrado + aportado neto.
