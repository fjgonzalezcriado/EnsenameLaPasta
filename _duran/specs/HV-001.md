### Referencias entre proyectos (Clean Architecture)

| Proyecto | Referencia a | Justificación |
|---|---|---|
| Web | Application, Infrastructure | Composición y DI |
| Application | Domain | Define interfaces y servicios |
| Infrastructure | Application, Domain | Implementa interfaces |
| Domain | — | Capa pura sin dependencias |
| Tests | Web, Application, Domain, Infrastructure | Acceso a todo lo testable |

> ⚠️ Application **NO** referencia a Infrastructure. Es regla inviolable.

### Lecciones Aprendidas

1. **`dotnet new sln` en SDK 10.0.300 genera `.slnx` por defecto, no `.sln`.** Hay que apuntar los comandos `dotnet sln <archivo> add ...` al archivo `.slnx` exacto. Si necesitas el formato clásico, usar `dotnet new sln --format sln`.
2. **`TreatWarningsAsErrors=true` en .NET 10 con templates default no produce warnings.** Buen flag para activar desde el inicio: previene drift de calidad.
3. **El hook PowerShell que reformatea `_duran/ESTADO_PROYECTO.json`** convierte apóstrofos `'` a `'` (escape JSON literal), lo que rompe edits por matching exacto del Edit tool. Lección: para modificar ese JSON, usar `ConvertFrom-Json` + `ConvertTo-Json` desde PowerShell en lugar de Edit literal.
