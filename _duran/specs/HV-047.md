## Contexto
El import de HV-018 solo creaba **posiciones abiertas** (`symbol, entry, qty[, date]`). Se amplía para importar también **trades cerrados** (con precio de salida y fecha de cierre), completando el histórico.

## Solución (backend)
`PositionService.ImportCsvAsync` acepta dos columnas opcionales más:
`symbol, entry, qty[, date[, exit[, closeDate]]]`.
- Si la fila trae **`exit`** (precio de salida > 0), se importa como **trade cerrado**: se `OpenAsync` y luego `CloseAsync(exit, closeDate ?? openedAt)`. Si no, sigue siendo posición abierta (comportamiento HV-018).
- **Pre-validación** por fila para no dejar posiciones a medio abrir: `exit` inválido → error; `closeDate` sin `exit` → error; `closeDate` anterior a la apertura → error (se rechaza **antes** de abrir, evitando estado parcial).
- Reutiliza el parser existente (cabecera opcional, delimitador `,`/`;` con coma decimal, fechas múltiples). Las filas con error se reportan por línea y no abortan el resto.
- UI: el modal "📥 Importar CSV" documenta las nuevas columnas y el ejemplo (abierta vs cerrada).

## Criterios de aceptación
- [x] Fila con `exit` → trade cerrado (ExitPrice/ClosedAt/RealizedPnL correctos)
- [x] Fila sin `exit` → posición abierta (compatibilidad HV-018)
