## Descripción

Implementar la estrategia automática **Moving Average Crossover**: comprar cuando la MA corta cruza por encima de la MA larga, cerrar la posición cuando la cruza por debajo. La estrategia consume los `MarketTick` que produce HV-004 mediante un **bus in-process** (`Channel<T>`), lo que evita polling de BD y mantiene latencia mínima.

Las operaciones (apertura/cierre de `Trade`) se persisten via `IOrderService` en `TradingDbContext`. Regla de posición: **máximo 1 trade abierto por símbolo** (simplificación MVP).

## Objetivo

Cerrar el "cerebro" del simulador. Al finalizar HV-005:
- El generador HV-004 emite ticks → la estrategia los procesa → genera Trades reales en BD.
- Cada `Trade` se abre y cierra con su PnL realizado calculado.
- Sin UI todavía (HV-006), pero los datos ya viven y se mueven.

### 2. `ChannelTickBus` (Infrastructure)

```csharp
using System.Threading.Channels;
using Comillas.AITradingSimulator.Application.Common.Interfaces;
using Comillas.AITradingSimulator.Domain.Entities;

namespace Comillas.AITradingSimulator.Infrastructure.MarketData;

public sealed class ChannelTickBus : ITickBus
{
    private readonly Channel<MarketTick> _channel = Channel.CreateBounded<MarketTick>(
        new BoundedChannelOptions(1000)
        {
            FullMode = BoundedChannelFullMode.DropOldest,
            SingleReader = true,
            SingleWriter = false
        });

    public ValueTask PublishAsync(MarketTick tick, CancellationToken cancellationToken = default)
        => _channel.Writer.WriteAsync(tick, cancellationToken);

    public IAsyncEnumerable<MarketTick> SubscribeAsync(CancellationToken cancellationToken = default)
        => _channel.Reader.ReadAllAsync(cancellationToken);
}
```

> `DropOldest` evita backpressure si la estrategia se atasca; perder algún tick en MVP no es crítico (el siguiente reactiva la lógica).

### 7. `MovingAverageCrossoverStrategy` (Application)

`Application/Strategies/MovingAverageCrossoverStrategy.cs`

Mantiene `Queue<decimal>` rolling por símbolo (corta y larga). Detecta el momento exacto del cruce comparando el estado actual (`short > long`) con el anterior.

```csharp
using Comillas.AITradingSimulator.Application.Common.Options;
using Comillas.AITradingSimulator.Domain.Entities;
using Comillas.AITradingSimulator.Domain.Enums;
using Microsoft.Extensions.Options;

namespace Comillas.AITradingSimulator.Application.Strategies;

public sealed class MovingAverageCrossoverStrategy : IStrategy
{
    private readonly StrategyOptions _options;
    private readonly Dictionary<string, Queue<decimal>> _shortWindows = new();
    private readonly Dictionary<string, Queue<decimal>> _longWindows = new();
    /// <summary>Estado del último cruce conocido por símbolo. null = aún sin datos suficientes.</summary>
    private readonly Dictionary<string, bool> _wasShortAbove = new();

    public MovingAverageCrossoverStrategy(IOptions<StrategyOptions> options)
    {
        _options = options.Value;
        if (_options.ShortWindow <= 0 || _options.LongWindow <= 0)
            throw new ArgumentException("Windows must be > 0");
        if (_options.ShortWindow >= _options.LongWindow)
            throw new ArgumentException("ShortWindow debe ser < LongWindow");
    }

    public TradeSignal? OnTick(MarketTick tick)
    {
        var symbol = tick.Symbol;

        var shortW = _shortWindows.TryGetValue(symbol, out var sw) ? sw : (_shortWindows[symbol] = new Queue<decimal>());
        var longW = _longWindows.TryGetValue(symbol, out var lw) ? lw : (_longWindows[symbol] = new Queue<decimal>());

        Enqueue(shortW, tick.Price, _options.ShortWindow);
        Enqueue(longW, tick.Price, _options.LongWindow);

        // No emitir señal hasta tener ambas ventanas llenas
        if (longW.Count < _options.LongWindow) return null;

        var shortMa = Average(shortW);
        var longMa = Average(longW);
        var shortAbove = shortMa > longMa;

        if (!_wasShortAbove.TryGetValue(symbol, out var previousShortAbove))
        {
            _wasShortAbove[symbol] = shortAbove;
            return null;  // primer dato completo, sin señal
        }

        if (shortAbove == previousShortAbove)
            return null;  // sin cambio = sin cruce

        _wasShortAbove[symbol] = shortAbove;
        return shortAbove ? TradeSignal.Buy : TradeSignal.Sell;
    }

    private static void Enqueue(Queue<decimal> queue, decimal value, int maxSize)
    {
        queue.Enqueue(value);
        while (queue.Count > maxSize) queue.Dequeue();
    }

    private static decimal Average(Queue<decimal> queue)
    {
        decimal sum = 0m;
        foreach (var v in queue) sum += v;
        return sum / queue.Count;
    }
}
```

`Application/Services/OrderService.cs`

```csharp
using Comillas.AITradingSimulator.Application.Common.Interfaces;
using Comillas.AITradingSimulator.Domain.Entities;
using Comillas.AITradingSimulator.Domain.Enums;
using Microsoft.EntityFrameworkCore;

namespace Comillas.AITradingSimulator.Application.Services;

public sealed class OrderService : IOrderService
{
    private readonly ITradingDbContext _db;

    public OrderService(ITradingDbContext db) => _db = db;

    public async Task<Trade?> BuyAsync(string symbol, decimal entryPrice, decimal quantity, DateTime nowUtc, CancellationToken ct = default)
    {
        var sym = symbol.ToUpperInvariant();
        var hasOpen = await _db.Trades.AnyAsync(t => t.Symbol == sym && t.Status == TradeStatus.Open, ct);
        if (hasOpen) return null;

        var trade = Trade.Open(sym, entryPrice, quantity, nowUtc);
        _db.Trades.Add(trade);
        await _db.SaveChangesAsync(ct);
        return trade;
    }

    public async Task<Trade?> CloseAsync(string symbol, decimal exitPrice, DateTime nowUtc, CancellationToken ct = default)
    {
        var sym = symbol.ToUpperInvariant();
        var openTrade = await _db.Trades
            .Where(t => t.Symbol == sym && t.Status == TradeStatus.Open)
            .OrderBy(t => t.CreatedAt)
            .FirstOrDefaultAsync(ct);

        if (openTrade is null) return null;

        openTrade.Close(exitPrice, nowUtc);
        await _db.SaveChangesAsync(ct);
        return openTrade;
    }
}
```

> `OrderService` vive en Application porque solo depende de `ITradingDbContext` (también en Application). No tiene dependencias de Infrastructure.

### 9. `StrategyExecutionService` (Infrastructure)

`Infrastructure/Strategy/StrategyExecutionService.cs`

```csharp
using Comillas.AITradingSimulator.Application.Common.Interfaces;
using Comillas.AITradingSimulator.Application.Common.Options;
using Comillas.AITradingSimulator.Application.Strategies;
using Comillas.AITradingSimulator.Domain.Enums;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;
using Microsoft.Extensions.Logging;
using Microsoft.Extensions.Options;

namespace Comillas.AITradingSimulator.Infrastructure.Strategy;

public sealed class StrategyExecutionService : BackgroundService
{
    private readonly ITickBus _bus;
    private readonly IStrategy _strategy;
    private readonly IServiceScopeFactory _scopeFactory;
    private readonly IOptionsMonitor<StrategyOptions> _options;
    private readonly TimeProvider _timeProvider;
    private readonly ILogger<StrategyExecutionService> _logger;

    public StrategyExecutionService(
        ITickBus bus, IStrategy strategy, IServiceScopeFactory scopeFactory,
        IOptionsMonitor<StrategyOptions> options, TimeProvider timeProvider,
        ILogger<StrategyExecutionService> logger)
    {
        _bus = bus; _strategy = strategy; _scopeFactory = scopeFactory;
        _options = options; _timeProvider = timeProvider; _logger = logger;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        _logger.LogInformation("Iniciando estrategia MA Crossover. ShortWindow={Short} LongWindow={Long}",
            _options.CurrentValue.ShortWindow, _options.CurrentValue.LongWindow);

        try
        {
            await foreach (var tick in _bus.SubscribeAsync(stoppingToken))
            {
                var signal = _strategy.OnTick(tick);
                if (signal is null) continue;

                using var scope = _scopeFactory.CreateScope();
                var orders = scope.ServiceProvider.GetRequiredService<IOrderService>();
                var now = _timeProvider.GetUtcNow().UtcDateTime;

                try
                {
                    Trade? result;
                    if (signal == TradeSignal.Buy)
                    {
                        result = await orders.BuyAsync(tick.Symbol, tick.Price, _options.CurrentValue.Quantity, now, stoppingToken);
                        if (result is not null)
                            _logger.LogInformation("BUY {Symbol} @ {Price} qty={Qty}", result.Symbol, result.EntryPrice, result.Quantity);
                    }
                    else
                    {
                        result = await orders.CloseAsync(tick.Symbol, tick.Price, now, stoppingToken);
                        if (result is not null)
                            _logger.LogInformation("SELL {Symbol} @ {Price} pnl={PnL}", result.Symbol, result.ExitPrice, result.RealizedPnL);
                    }
                }
                catch (Exception ex) when (ex is not OperationCanceledException)
                {
                    _logger.LogError(ex, "Error ejecutando señal {Signal} para {Symbol}", signal, tick.Symbol);
                }
            }
        }
        catch (OperationCanceledException)
        {
            _logger.LogInformation("Estrategia detenida por cancelación.");
        }
    }
}
```

## Notas de implementación

- **Pub-sub vs Polling**: `Channel<T>` mantiene latencia mínima sin polling. Cost: el `ChannelTickBus` debe estar registrado como Singleton para que generator (Singleton-friendly) y strategy (Singleton-friendly) lo compartan correctamente.
- **`Channel.SingleReader = true`**: solo hay UN suscriptor (la estrategia). Si en futuro queremos múltiples (ej: persistir métricas en paralelo), cambiar a un esquema pub-sub diferente (`IObservable<T>` o `System.Threading.Channels` con múltiples readers via fan-out).
- **`DropOldest` en backpressure**: si la estrategia se atasca, perdemos ticks viejos pero el flujo no se bloquea. En MVP es aceptable.
- **`IOrderService` en Application, no Infrastructure**: como solo usa `ITradingDbContext` (que ya vive en Application), no requiere mover nada a Infrastructure.
- **Regla "1 posición abierta por símbolo"**: simplificación deliberada. Permite que el `WasShortAbove` interno de la estrategia coincida con el estado real de posiciones (si la estrategia emite Buy y ya hay open, `BuyAsync` retorna null y se loggea pero no rompe).
- **Race condition potencial**: el estado interno de `_wasShortAbove` puede divergir del estado de BD si reiniciamos la app (el dict se pierde). Solución MVP: aceptar el "warm-up" de cada arranque (mientras se llenan ventanas, no emite señales). Una opción futura sería persistir el estado de la estrategia.
- **Tests con `:memory:`**: para `OrderServiceTests` reusamos el patrón de `TradingDbContextTests` (conexión `SqliteConnection :memory:` mantenida en vida del test).

### Lecciones Aprendidas

1. **`Channel<T>` con `SingleReader=true` + `DropOldest`** es el patrón canónico para pub-sub in-process con un único consumidor. Si la estrategia se ralentiza, perdemos los ticks más antiguos sin bloquear al generador. Aceptable en simulador donde nuevos ticks llegan inmediatamente.
2. **Singleton (provider, bus, strategy) + Scoped (OrderService, DbContext) via `IServiceScopeFactory`**: patrón consistente con HV-004. Los servicios sin estado de BD pueden ser Singleton; los que tocan BD necesitan Scope per operation.
3. **Estado de la estrategia es in-memory y se pierde al reiniciar**: arranque con BD existente significa que el primer puñado de ticks no genera señales (las ventanas se llenan otra vez). Es aceptable para MVP. Una mejora futura sería rehidratar las ventanas desde los últimos N MarketTicks de BD.
4. **Detección de cruce por cambio de estado booleano** es más robusta que comparar valores literales `prev_shortMa vs prev_longMa`: maneja correctamente igualdades exactas y no genera falsas señales por ruido infinitesimal.
5. **Test de "precio estable"** validó que la implementación no emite señales fantasma cuando short==long. Un caso de borde fácil de olvidar pero importante.
